# Kafka 기반의 선착순 쿠폰 발급 시스템

### **1. CouponController**
- **역할**: HTTP 요청 수신 및 응답 처리
- **담당**: API 엔드포인트 제공, 요청/응답 데이터 변환
- **핵심 메서드**: `requestCouponIssue()` - 쿠폰 발급 요청을 받아 서비스로 전달

### **2. CouponService**
- **역할**: 비즈니스 로직 조합 및 트랜잭션 관리
- **담당**:
    - 쿠폰 존재 확인
    - 이벤트 발행을 통한 비동기 처리 시작
- **핵심 메서드**: `enqueue()` - 쿠폰 발급 이벤트를 발행

### **3. CouponEventListener**
- **역할**: 도메인 이벤트 처리 및 아웃박스 패턴 구현
- **담당**:
    - **BEFORE_COMMIT**: 아웃박스에 이벤트 저장 (트랜잭션 안전성)
    - **AFTER_COMMIT**: 카프카로 메시지 발행

### **4. CouponOutboxRepository**
- **역할**: 아웃박스 패턴을 위한 이벤트 저장소
- **담당**: 이벤트 영속화, 미처리 이벤트 조회, 상태 관리

### **5. CouponEventPublisher**
- **역할**: 카프카 메시지 발행
- **담당**: 도메인 이벤트를 JSON으로 직렬화하여 카프카 토픽으로 전송

### **6. CouponScheduler**
- **역할**: 주기적 작업 스케줄링
- **담당**: 매 1분마다 발급 가능한 쿠폰들을 찾아 처리 시작

### **7. CouponIssueProcessor**
- **역할**: 실제 쿠폰 발급 비즈니스 로직 처리
- **담당**:
    - Redis 대기열에서 선착순 사용자 조회
    - 배치 단위로 쿠폰 발급 처리
    - 성공/실패 결과를 캐시에 저장

### **8. CouponEventConsumer**
- **역할**: 카프카 메시지 소비 및 최종 발급 처리
- **담당**:
    - 배치 메시지 수신
    - 아웃박스와 메시지 매칭
    - 실제 DB에 쿠폰 발급 데이터 저장

## 현재 구조의 특징

1. **이중 처리 구조**: 스케줄러를 통한 대기열 처리 + 카프카 컨슈머를 통한 실제 발급
2. **아웃박스 패턴**: 트랜잭션 안전성을 위한 이벤트 저장
3. **Redis 기반 대기열**: 선착순 처리를 위한 타임스탬프 기반 정렬
4. **배치 처리**: 성능 최적화를 위한 일괄 처리
