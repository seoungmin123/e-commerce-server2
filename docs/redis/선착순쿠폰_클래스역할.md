# Redis 기반의 선착순 쿠폰 발급 시스템

### **1. CouponController**
- **역할**: HTTP 요청 처리 및 응답
- **담당**:
    - `/issue-requests`: 대기열 방식 쿠폰 발급 요청
    - `/issue`: 즉시 쿠폰 발급 (분산락 사용)
- **특징**: 두 가지 발급 방식을 모두 제공

### **2. CouponService**
- **역할**: 비즈니스 로직 처리 및 트랜잭션 관리
- **핵심 메서드**:
    - `requestCouponIssue()`: Redis 대기열에 요청 추가
    - `issueCoupon()`: 분산락을 이용한 즉시 발급
- **특징**: Redisson 분산락 사용으로 동시성 제어

### **3. CouponScheduler**
- **역할**: 주기적 배치 처리
- **담당**: 매 1분마다 발급 가능한 쿠폰들을 찾아 처리 시작
- **특징**: ShedLock으로 중복 실행 방지

### **4. CouponIssueProcessor**
- **역할**: 실제 배치 쿠폰 발급 처리
- **담당**:
    - Redis ZSet에서 타임스탬프 순으로 사용자 조회
    - 배치 단위로 쿠폰 발급 처리
    - 성공/실패 결과를 Redis에 저장
- **특징**: 메모리에서 쿠폰 수량 증가 후 캐시만 업데이트

### **5. CouponRepositoryImpl**
- **역할**: 데이터 접근 계층 조합
- **담당**: JPA Repository와 Cache Repository를 조합하여 데이터 접근

### **6. CouponCacheRepository**
- **역할**: Redis 기반 캐시 관리
- **핵심 기능**:
    - **ZSet**: 타임스탬프 기반 대기열 (`coupon:{id}:requests`)
    - **Set**: 발급 완료 사용자 관리 (`coupon:{id}:issued`)
    - **Set**: 발급 실패 사용자 관리 (`coupon:{id}:failed`)
- **특징**: Pipeline을 사용한 배치 처리로 성능 최적화

### **7. DistributedLock (RedissonLockAspect)**
- **역할**: 분산 환경에서의 동시성 제어
- **담당**: Redisson을 이용한 분산락 AOP 구현
- **특징**: SpEL 표현식으로 동적 락 키 생성

## Redis 기반 시스템의 특징

### **장점**
1. **빠른 응답**: Redis의 메모리 기반 처리로 빠른 성능
2. **정확한 순서**: ZSet의 타임스탬프 기반 정렬로 선착순 보장
3. **이중 발급 방식**: 즉시 발급과 대기열 발급 두 방식 제공
4. **동시성 제어**: Redisson 분산락으로 안전한 동시 처리

### **단점**
1. **데이터 일관성**: 메모리에서만 수량 증가, DB와 불일치 가능
2. **단일 장애점**: Redis 장애 시 대기열 데이터 손실
3. **복잡한 상태 관리**: 여러 Redis 키로 상태 분산 관리
4. **배치 처리 지연**: 최대 1분의 처리 지연 가능

이 구조는 **Redis 중심의 순수 캐시 기반 시스템**으로, Kafka 없이도 선착순 처리가 가능하지만 내구성과 확장성에서 제약이 있습니다.
