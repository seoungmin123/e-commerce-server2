# 3일 인기상품 Top-5 캐시 (RedisTemplate 기반) 설계 문서

---

## 1. 문서 목적

- 최근 3일 판매량 기준 **Top-5 인기상품**을 빠르고 안정적으로 제공하는 캐시 설계를 설명한다.
- 캐시 자료구조, 스냅샷 교체 방식, 동시성/일관성 보장 수준을 정리한다.
- 운영/테스트 전략과 개선 포인트를 함께 제시한다.

---

## 2. 시스템 개요

- **DB 집계**: 최근 3일 판매량을 기준으로 상품 판매량 집계
- **캐시 스냅샷**: DB 결과를 Redis에 적재하고, TEMP → CURRENT 원자적 스왑
- **조회 흐름**: 애플리케이션은 **항상 캐시(CURRENT)**만 조회
- **스케줄러(10분 주기)**: 새로운 TEMP 준비 → CURRENT와 교체 → (선택) 이전 CURRENT를 BACKUP으로 보존
- **장애 대비**: CURRENT 비면 BACKUP으로 폴백, BACKUP도 없으면 빈 리스트 반환

---

## 3. 주요 컴포넌트 및 책임

### 3.1 `ProductService`

- 비즈니스 진입점.
- 캐시 매니저(`PopularProductCacheManager`)에 조회 위임.

### 3.2 `PopularProductCacheManager`

- 캐시 **조회/리프레시 정책** 캡슐화.
- TEMP 준비 여부 확인, 스왑, 폴백 처리 담당.

### 3.3 `ProductCacheRepository`

- Redis 접근 래퍼.
- ZSET/HASH 조작, multiGet, rename, expire 등 I/O 처리.

### 3.4 `ProductScheduler`

- 10분마다 캐시 리프레시 실행.
- ShedLock으로 멀티 인스턴스 중복 실행 방지.

### 3.5 `RedisConfig`

- `RedisTemplate` , `RedisCacheManager` 설정.

### 3.6 DTO

- `PopularProductQuery`: DB 집계 결과 DTO (productId, price, totalQuantity 등).
- `PopularProductInfo`: 응답/캐시용 DTO (price, totalQuantity). JSON ↔ DTO 변환.

---

## 4. 데이터 모델 & 자료구조 (REDIS)

각 스냅샷은 **ZSET + HASH** 2종 키로 구성된다.

| 스냅샷 구분 | 키 예시 | 자료구조 | 멤버/값 |
| --- | --- | --- | --- |
| TEMP | `products:popular:temp:*` | ZSET/HASH | 적재 중인 스냅샷 |
| CURRENT | `products:popular:current:*` | ZSET/HASH | 조회용 최신 스냅샷 |
| BACKUP | `products:popular:backup:*` | ZSET/HASH | 폴백용 백업 스냅샷 |
- **ZSET**: `member = productId(Long)`, `score = totalQuantity(Double)`
- **HASH**: `field = productId(String)`, `value = PopularProductInfo JSON`

---

## 5. 처리 흐름 (시퀀스)

### 5.1 캐시 리프레시

1. DB에서 최근 3일간 Top-N 집계 (`orderRepository.findTopFivePopularProducts()`)
2. TEMP 키에 ZSET/HASH 적재
3. TEMP가 준비 완료되면 → CURRENT로 **RENAME(원자적 스왑)**
4. 기존 CURRENT는 BACKUP으로 보존, TTL 부여(30분)

### 5.2 조회

1. CURRENT ZSET에서 Top-N 조회 (`reverseRangeWithScores`)
2. HASH에서 멀티겟 후 JSON 역직렬화 → `PopularProductInfo` 리스트 반환
3. CURRENT 비면 BACKUP 폴백 → 그래도 없으면 빈 리스트

---

## 6. 선착순/일관성 보장 

- **스냅샷 원자성**: RENAME 연산이 원자적이므로 깨진 스냅샷 노출 없음
- **조회 일관성**: TEMP가 완성되기 전까지는 기존 CURRENT 유지
- **중복 방지**: ShedLock으로 멀티 인스턴스 환경에서도 한 번만 스케줄러 실행

---

## 7. 직렬화 설정

- **Key**: `StringRedisSerializer`
- **ZSET 멤버/Value**: `GenericToStringSerializer<Long>`
- **HASH Value**: `PopularProductInfo` JSON 문자열

---

## 8. 예외/실패 시나리오

| 시나리오 | 동작 |
| --- | --- |
| TEMP 비었음 | 스왑 스킵, TEMP 삭제, CURRENT 유지 |
| CURRENT 없음 | BACKUP 폴백 시도 |
| BACKUP도 없음 | 빈 리스트 반환 |
| 리프레시 실패 | TEMP 정리, 예외 로깅, CURRENT 영향 없음 |

```java
@Scheduled(cron = "0 */10 * * * *")
@SchedulerLock(name = "refreshPopularProducts", lockAtLeastFor = "60s", lockAtMostFor = "60s")
public void refreshPopularProducts() { ... }

```

- ShedLock LockProvider(Redis/JDBC)로 단일 실행 보장

---

## 10. 성능/복잡도 (빅오)

- ZSET 삽입: O(log N)
- ZSET 조회 Top-N: O(log N + N)
- HASH 멀티겟: O(N)
- 스왑(RENAME): O(1)

---

## 11. 용어 정의

- **스냅샷**: 특정 시점의 인기상품 집계 결과. Redis CURRENT 키로 유지.
- **스왑**: TEMP와 CURRENT를 교체하는 원자적 RENAME 동작.
- **폴백**: 조회 시 CURRENT 없을 때 BACKUP을 대신 사용하는 동작.
